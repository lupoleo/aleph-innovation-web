# Agentic Portfolio

Agentic Portfolio is Aleph Innovation's first active R&D project.

It explores how deterministic portfolio analysis, quantitative risk controls,
structured research, probabilistic AI and agentic decision-support can operate
inside a single engineered lifecycle.

The project is not designed around the assumption that an LLM is the
application. Instead, probabilistic AI operates inside explicit software
contracts, portfolio constraints, validation gates and human execution
authority.

## What the project explores

Agentic Portfolio combines several engineering domains:

- deterministic portfolio and position analysis;
- technical and quantitative market analysis;
- portfolio risk and concentration assessment;
- evidence-based research;
- structured opportunity scoring;
- portfolio-aware filtering;
- portfolio risk simulation;
- AI-assisted CIO decision support;
- explicit execution planning;
- manual execution and outcome tracking.

## Canonical lifecycle

The current conceptual lifecycle is:

`SCAN → RESEARCH → OPPORTUNITY SCORING → PORTFOLIO FILTER → INSTRUMENT SELECTION → POSITION SIZING → TRADE PROPOSAL → PORTFOLIO RISK SIMULATION → CIO DECISION → EXECUTION PLAN → MANUAL EXECUTION → OUTCOME`

Each stage has a distinct responsibility.

Deterministic services own numerical computation, state, constraints and
validation wherever reproducible rules are possible.

Probabilistic AI contributes semantic interpretation, research synthesis,
contextual reasoning and candidate assessments where deterministic logic alone
is insufficient.

## Engineering principles

The project follows several core principles:

1. **Deterministic where certainty is possible.**
2. **Probabilistic where interpretation creates value.**
3. **Typed contracts between lifecycle stages.**
4. **Explicit provenance and evidence boundaries.**
5. **Fail-closed behaviour when required information is missing or invalid.**
6. **Human authority remains outside automated execution.**
7. **Testing includes both conventional regression and semantic validation.**
8. **Architecture, failures and lessons learned are documented as the system evolves.**
